# Автоматическое обновление KARLO WEAR

Проверки запускаются для pull request и изменений main: установка по lock-файлу,
генерация Prisma, TypeScript, модульные и интеграционные тесты, сборка.
После успешных проверок main выкладывается на VPS через GitHub Actions.

Workflow: `.github/workflows/ci-deploy.yml`. Серверный скрипт:
`scripts/deploy-release.sh`. Источники при настройке синхронизированы с рабочей
версией `/srv/karlo-wear/current`, без `.env`, базы, чеков и загрузок.

В GitHub Actions Secrets хранятся DEPLOY_HOST, DEPLOY_USER, DEPLOY_SSH_KEY,
DEPLOY_KNOWN_HOSTS. Значения ключей не добавляются в Git. Host key проверяется
строго, environment production разрешает только main. Переменная репозитория
DEPLOY_ENABLED=true включает выкладку; false оставляет только проверки.

Выкладки выполняются последовательно; сервер дополнительно использует flock.
Новая версия собирается до остановки API. После остановки создаётся дамп базы
с проверкой оглавления, затем переключается ссылка current и проверяется
готовность API. При ошибке скрипт возвращает предыдущую версию кода и статики.
База автоматически не откатывается. Старые файлы assets сохраняются для
открытых страниц покупателей. На сервере остаются релизы и резервные копии;
свободное место следует контролировать.

Новые, изменённые или пропущенные применённые миграции останавливают выкладку.
Миграции базы требуют отдельного рассмотрения и резервного копирования.
Workflow не запускает seed и не удаляет заказы. Изменение клиентских .env на
сервере применяется при следующей сборке. Основная служба:
karlo-wear-api.service; ежедневная копия: karlo-wear-backup.timer.

Доступ использует отдельный SSH-ключ root с отключёнными forwarding и PTY.
Ключ позволяет выполнять код с правами root; доступ к main и изменению
workflow следует предоставлять только доверенным разработчикам.
